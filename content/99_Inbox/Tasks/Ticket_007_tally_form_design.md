# 📋 에이전트 태스크 티켓 [007]

## 🎯 목표
**MS-2: "낚시" 자산**의 핵심인 **Tally 설문지(Waitlist Form)**를 설계합니다.
단순한 "대기 등록" 폼이 아니라, 개발자의 **고통점(Pain Points)**을 자극하여 "이 도구가 내 문제를 해결해 주겠구나"라는 기대감을 심어주는 것이 목표입니다.

## 🚩 관련 마일스톤
*   **대상:** [[01_Strategy/Milestones#MS-2|MS-2: "낚시" 자산]]
*   **성공 기준:**
    - [ ] **Tally 폼:** 타겟팅된 질문(고통점)이 포함된 라이브 URL (또는 초안)

## 📂 컨텍스트 & 리소스
*   **전략:** [[01_Strategy/Target_Persona]] (타겟 페르소나: 번역 품질에 지친 1인 개발자)
*   **도구:** Tally.so (무료 계정 활용)
*   **참고:** [[04_Marketing/Beta_Launch_Kit]] (베타 런칭 키트)

## 🛠️ 요구사항 (단계별)
1.  **후킹 질문 설계:**
    *   "번역 검수에 얼마나 시간을 쓰시나요?" 같은 단순 질문 대신,
    *   "번역가가 게임 변수(`{player_name}`)를 깨먹어서 빌드가 터진 적이 있나요?" 같은 **구체적 고통**을 건드리는 질문 3~4개 작성.
2.  **솔루션 암시:**
    *   질문 자체가 IndieLoca의 기능(태그 안전, 캐릭터 톤 유지)을 암시하도록 구성.
3.  **CTA (Call to Action) 문구:**
    *   "베타 신청하기" 대신 "내 게임 번역 1시간 만에 LQA 끝내기" 등 혜택 중심 문구 작성.
4.  **Tally 폼 구조안 작성:**
    *   헤더 이미지 / 제목 / 설명 / 질문 / 이메일 수집 필드 / 감사 페이지 메시지.

## ✅ 성공 기준 (완료 정의)
*   [ ] **설문 문항 확정:** 고통점 자극 질문 3종 + 선택지.
*   [ ] **Tally 구조안:** 제목, 설명, 질문 순서가 정리된 마크다운 문서.
*   [ ] **(옵션) Tally 링크:** 가능하다면 실제 Tally 폼 생성 후 링크 공유.

---
**에이전트 지침:**
1. 개발자의 언어("빌드 에러", "태그", "변수")를 사용할 것.
2. 너무 길지 않게(1분 이내 완료) 설계할 것.
